# 前端共享交接与日志规则

`frontend/work-logs/` 用于可能需要后端或其他协作者阅读、随任务提交至 GitHub 的交接与验收记录。普通工作过程默认写入 `frontend/local-work-logs/`，该目录由根 `.gitignore` 忽略。两类记录只涵盖前端及前端相关联调；纯后端日志由后端自行约定。

## 写到哪里

| 内容 | 位置 |
| --- | --- |
| 日常开发过程、阅读规划、Git同步/提交补记、排查尝试 | `frontend/local-work-logs/` |
| 原始截图、临时检查输出、完整运行记录 | 本地日志同名附件目录 |
| 接口差异、后端缺陷、跨端依赖、行为变化与接手待办 | `frontend/work-logs/` |
| 跨端验收结论、支持范围、失败复现和必要脱敏证据 | 共享记录及同名附件目录 |

一个任务可以有完整本地日志和精简共享交接。没有协作事项时只写本地日志。共享记录必须自包含，不链接或依赖本地忽略文件；本地日志可以引用共享记录。共享索引只列共享文件。新检出仓库没有本地日志时直接创建目录即可。

## 维护流程

1. 开始任务先读根/前端 AGENTS、本说明、相关共享记录及本机可用的近期日志，核对分支和 Git 状态。
2. 写操作前先建立本地日志，状态为“进行中”。两类记录统一使用 Asia/Shanghai 日期和 `YYYY-MM-DD-主题.md`；同一任务恢复更新原文件，跨日继续不必重命名。
3. 本地日志记录目标、允许范围、初始状态、计划、实际改动、命令与结果、失败、未验证内容、下一步及真实提交/推送情况。结束或中断前补齐状态。
4. 出现需要协作的结论时提炼共享记录，注明任务/基线、影响、接口与支持范围、实际证据、限制和责任方。保留历史时点，不能把旧测试改写成本轮已验证。
5. 运行已有检查脚本前显式将 `OUTPUT_DIR` 等输出目录指向本地同名附件目录；脚本旧默认值可能落到共享历史路径。只复制必要的脱敏结果作为共享证据，明确是否省略截图/原始输出，不把省略内容作为共享结论唯一依据。
6. 区分代码实现、检查通过、真实 API 联调和目标环境验收；fixture/mock不能替代真实服务。两类目录均禁止密码、Cookie、CSRF token、API key等敏感内容。
7. 本地内容不暂存、不用 `git add -f` 提交。共享记录按用户授权纳入任务提交，写日志不增加提交/推送权限。Git ignore不会取消旧文件跟踪：迁移旧日志应保留本地内容、核对引用并说明旧路径删除，不改写历史。

## 本地日志模板

保存到 `frontend/local-work-logs/YYYY-MM-DD-主题.md`：

```markdown
# 工作日志：主题

日期：YYYY-MM-DD（Asia/Shanghai）
任务 ID：
状态：进行中

## 开始记录

- 目标与允许修改范围：
- 初始 Git 分支/基线/未提交改动：
- 执行计划与已知阻塞：

## 实际改动与决定

## 验证结果

- 命令、退出码与结果：
- 真实 API / 目标环境：
- 失败、未执行与未验证：

## 结束记录

- 状态、未完成事项与下一步：
- 实际提交/推送情况：
```

## 共享交接模板

仅有协作事项时保存到 `frontend/work-logs/YYYY-MM-DD-主题.md`：

```markdown
# 交接：主题

日期 / 任务 ID / 代码基线：
当前状态与影响范围：

## 接手者需要知道的变化

- 接口/行为/兼容性与前后端依赖：

## 证据与验证边界

- 复现步骤或命令、实际结果、预期结果：
- 随仓库提供的脱敏证据、支持范围与未验证事项：

## 待办与责任方

- 接手任务、负责人和验收条件：
```
