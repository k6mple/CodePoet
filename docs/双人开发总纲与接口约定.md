# 代码诗：双人开发总纲（基础演示版）

> 修订：2026-11-05。本版面向**两名基础 CRUD 开发者 + AI 辅助**，替代此前全量基础功能必做的安排。截止 2026-11-21 12:00 GMT+8。
>
> 开发顺序与完成状态以 [交付计划与任务看板](./交付计划与任务看板.md) 为准；当前接口以 [接口文档](./接口文档.md) 和 [核心 OpenAPI](./openapi-core.json) 为准。[完整 OpenAPI](./openapi.json) 保留进阶契约，不是全部必做清单。

## 1. 交付目标与优先级

必须完整演示这条链：知识录入 → IR 模板/参数 → 审核发布 → 默认/语义创作 → 动画/IR 编辑 → 保存/收藏/历史 → 作品审核 → 旧快照复现 → 审计与备份。

| 级别 | 本期做什么 | 定位 |
| --- | --- | --- |
| P0 | 登录、固定模板默认生成/调参、Canvas、PNG 上传保存、重开 | 先证明应用可运行 |
| P1-A 核心必做 | 四角色、知识/本体/标签、模板版本审核、个人空间、筛选、基础导入导出/审计 | 主攻常规业务评分点 |
| P1-B 关键特色 | 小型规则语义、IR 子树/裁剪、时间轴叙事、完整来源与真实像素复现比较 | 必须有真实技术特色 |
| P1-C 高风险补充 | CSS/Turtle/WebGL、受限 DSL、安全策略管理 | 先验收主线，有时间挑一项 |
| P2 附加扩展 | 外部图谱、LLM、进阶 GPU、复杂质量评分、无头浏览器自动化 | 不挤占交付 |

不再要求所有基础项 100% 实现。尤其沙盒 5 分、四后端部分、安全策略部分为明确缺口。JSON IR 校验不等于代码沙盒，Canvas 一个后端不等于四后端。评分覆盖分析见看板，不承诺具体分数。

## 2. 唯一责任边界

| 范围 | A：后端与规则 | B：前端与 Canvas |
| --- | --- | --- |
| 所属目录 | backend/**、shared/schemas/**、后端脚本 | frontend/**、shared/demo/**、前端脚本 |
| 数据与业务 | API、SQLite、权限、审核、版本、导入导出/审计 | 页面/表单/列表/状态与操作流程 |
| 创作引擎 | 参数/IR 校验、确定性规则、子树、快照 | Canvas 图元/采样、参数交互、IR 编辑、时间轴 |
| 图片与复现 | 上传验证/持久化、manifest、Pillow RGBA 比较 | toBlob 导出、上传、按旧 IR 重绘、比较结果显示 |
| 演示数据 | 提供幂等 seed 入口，审核关联/约束 | 编写 12 条知识、3 个模板、8 条规则示例和演示稿 |
| 当前不承担 | Turtle/DSL/进程沙盒/无头浏览器调度 | WebGL/CSS 三适配器/Playwright 桥接/复杂可视化编辑器 |

A 每天给可调用 JSON/接口；B 先用相同 fixture 开发，然后切真实 API。两人各自负责职责目录的 Codex 会话，不让 AI 同时覆盖对方文件。根规范和接口只由 A 主改，B 提供最小复现反馈。

## 3. 简单的实现方案

- Next.js 16 App Router + React 19 + TypeScript + 一个现成组件库；页面列表/弹窗/JSON textarea 复用。2026-11-06 根据开发者熟悉度由 Vue/Vite 调整为 Next.js；交互与 Canvas 使用客户端组件，权威业务仍由 FastAPI 提供。
- FastAPI + Pydantic + 同步 SQLAlchemy + SQLite，本地 data/artifacts；一个应用实例。
- 浏览器 Canvas 是唯一必做渲染后端；PNG 在浏览器绘制后直接上传。基础版无需 Playwright/Node 导出服务、Xvfb、Ghostscript 或 cgroup。
- Python Pillow 只做 PNG 解码校验、空白统计和像素比较，不在基础版假冒其他绘图后端。
- 固定角色/动作权限，小词典/规则表，JSON 版本快照。没有图数据库、LLM 依赖、Redis/Celery、通用工作流和插件框架。
- 使用简单编号迁移或 Alembic 二选一，幂等种子；无需复杂 CI，但启动、构建和关键用例必须实际跑过。
- 后端可在 Windows 或 Linux 开发；基础版不依赖 Unix 进程资源限制。只有选做真实代码执行时才单独验证 Linux/WSL2。

## 4. 基础演示版的能力上限

当前配置名 core-demo，限制由后端常量/配置集中维护，不开发通用策略编辑器。

| 项目 | 当前上限/规则 |
| --- | --- |
| 画布 | 固定 800×600，支持画布内整数 viewport 裁剪 |
| 图元 | group/circle/polygon/polyline；最多 200 节点、2000 顶点、4 层 |
| 路径 | polygon 非自交/非零面积；circle 固定 64 段近似 |
| 材质 | 仅 flat；无用户 GLSL、图片 URL、HTML |
| 静态变换 | x/y/rotation/scaleX/scaleY；T×R×S，父矩阵乘子矩阵 |
| 动画 | 静态0，动画1000～5000ms；x/y/rotation/opacity，linear，同属性最多一轨 |
| 时间采样 | 动画前 from、后 to、中间线性，覆盖基础值；不按系统时间随机 |
| 保存帧 | 静态 [0]，动画 [0,floor(duration/2),duration]；最多 3 帧 |
| 参数 | 最多 16 项，number/integer/enum/boolean/color；默认/范围/绑定/简单约束 |
| 请求 | JSON≤256 KiB；规范化 IR≤2 MiB；导入 JSON≤5 MiB |
| 图片 | 每帧 PNG≤5 MiB，multipart 总体≤6 MiB；必须等于 viewport 尺寸 |

完整模型允许更大的扩展范围，但 core-demo 在业务校验中拒绝超出上表的输入。能力 API 同时列出四个后端，只有 Canvas.available=true；其他项给真实 unavailableReason。

首批三个模板为莲、竹、4 秒叙事。模板是节点/轨道 IR 加参数绑定，不是固定 PNG。generatorRef=ir，fragmentSource=null；可编程范围是 JSON IR，不能提交任意 Python/JS。

## 5. 必须保留的接口约定

- /api/v1；camelCase；字符串 ID；时间 UTC ISO 8601；分页 items/total/page/pageSize。
- 成功直接返回对象，错误 {error:{code,message,fieldErrors,requestId,details}}。
- Cookie 会话+CSRF，注册默认 creator，其他角色走管理员审批。管理员初始种子创建，不能自助注册提权。
- 可编辑对象 revision，写入 expectedRevision；冲突 409。模板/作品版本的 versionNumber 与 revision 分开。
- 私有资源按所有者校验，猜 ID 返回 404；普通角色直接调管理操作返回 403；禁止审核自己提交的版本。
- 已发布模板版本/作品内容不可覆盖；修改产生新版本。公开列表只展示已通过的版本。
- 未发布模板预览标记 unpublishedSource，派生后继续保留，不能通过换编辑模式公开送审。
- 公共数据可以只读预览；图片/帧下载也检查作品公开状态，不能暴露 data 目录。

## 6. 核心生成与保存协议（与旧版不同）

### 6.1 即时创作

1. B 选已发布模板，POST /generations，A 校验默认值/参数并返回不可变 generation。
2. B 用返回的 IR 本地 Canvas 预览；快速输入防抖 300ms，过期响应不能覆盖新画面。
3. P1-B 语义模式仍由 A 查知识/规则后实例化；B 不在页面关键词 if/else 换图。

### 6.2 浏览器导出并持久化

1. B 固定当前 generationId、IR hash 和 rendererVersion。
2. POST /render-jobs，executionMode=browser_upload，附 backend、timesMs、rendererVersion、clientEnvironment。
3. A 创建 status=running、phase=awaiting_frames 的记录；基础版不会启动浏览器子进程。
4. B 依次 seek 到采样时刻，等待绘制完成，Canvas.toBlob 得 PNG。
5. POST /render-jobs/{id}/frames，multipart 包含 file、timeMs、irHash。
6. A 验证任务归属/时效/输入一致、PNG 真实解码/大小/尺寸，计算 hash；全部时刻齐全后保存 manifest，status=succeeded、phase=completed。
7. B 得到成功任务后 POST /works，用匹配 generationId/renderJobId 保存。没成功不能显示已保存。

任务等待上传最多 5 分钟；下次查询/创建任务时清理超时状态即可，无需任务队列。每用户最多两个进行中的上传任务，不限制全局一个浏览器槽。上传终态可重查，同一时刻同 hash 重传幂等，不同内容返回 409。

这些图片来自客户端真实 Canvas，服务端验证文件和归属，**不证明它们一定由指定 IR 诚实绘制**。对本期宣教创作演示足够；若将来要求服务端可信渲染，再做隔离的浏览器桥接选做项。

### 6.3 复现

POST /work-versions/{id}/reproduce 读取旧 IR/参数/来源，创建新的 browser_upload 任务。B 加载旧 IR，按原时刻重绘上传；A 只比较原/新 PNG，不重新解释当前知识/规则。

comparison 返回 actual exactMatch/mae/differentPixelRatio。环境记录基于浏览器自报 UA、DPR=1、rendererVersion 和尺寸；这只是兼容性提示，不是硬件指纹认证。环境不同标 incompatible；环境相同也必须实际比较后才说像素一致。

## 7. 简化数据与审核

核心实体保留 User、KnowledgeEntity、Concept/Tag、MappingRule、Template/TemplateVersion、Generation、RenderJob、Work/WorkVersion、CreationSession/Snapshot、Review/Favorite/AuditLog。

把 IR/参数/规则内容/知识内容/编辑状态存 JSON 字段；不把每个图元/轨道拆成表。Snapshot 与作品版本分开：前者是编辑现场，后者绑定确定 generation+成功图片任务。

- 模板：draft → submitted → published/rejected，published 可 archived；送审后不可原地编辑。
- 作品：private → pending_review → published/rejected；新版本通过前旧公开版本继续展示。
- 快照恢复：复制旧现场为新当前态，保留恢复前历史，不自动运行任何代码。
- 审计：记录知识/模板/规则修改、审核、生成/上传/保存、导入导出，含 requestId 与关联 ID；不记录密码/Cookie。

## 9. Codex 使用方式

每次只给一个看板任务 ID，带允许目录、请求样例、成功/失败条件。读本文、自己的任务书和核心接口即可开始；不要让 AI 自动实现完整 OpenAPI 中的 P1-C/P2。

任务结束必须报告真实变更、运行命令/结果、未完成项；开发者亲自走页面验收。新依赖只解决眼前需要，不自动添加微服务/中间件。跨目录问题先发请求响应和最小复现，不让两个 Codex 相互覆盖。
