## 2. 分数目标与投入选择

原赛题是[基础 100 + 附加 50](PR.md)。当前非官方估分为基础 78～88、附加 2～4，合计 80～92；没有逐项扣分细则，不能保证得分。

| 投入方向 | 关联赛题权重 | 价值与顺序 | 规划预算（A/B 有效小时） |
| --- | --- | --- | --- |
| 稳定基线、契约与共用渲染协议 | 保护已覆盖业务域 | 第一优先；先消除集成阻塞 | 3 / 4 |
| 质量量化治理 | 附加 10 | 稳定提分主线：布局、色彩语义、输出信号/噪声与可执行建议 | 7 / 3 |
| 真实图谱联动 | 附加 15 | 高权重；11/13 中午前验证外部实体/关系/属性接口，有来源才投入 | 8 / 2，条件项 |
| CSS + 基础 WebGL + Turtle | 引擎适配器合计 5 | 同 IR 复用能加速；四套合计只有 5 分，不为最后一个适配器无限延期 | A 8、B 16，共用契约另计在首项 |
| 受限 DSL + AST/运行防护 + 策略 | 基础沙盒 5，关联运维配置 4 的缺口 | A 与 B 渲染任务同期推进，先证实部署隔离能力 | 11 / 3 |
| LLM 辅助 或 GPU 进阶 | 附加各 10 / 15 | 主线全过后最多一个；LLM 有真实凭据且先落地校验则优先 | LLM 5/2；GPU 1/6 |

这些权重有交叉，不能把「关联 4 分」再当 4 分新增；四后端不按每套 5 分计算。质量现有 2～4 分也不能再次叠加。按任务权重看，图谱和质量比为了四后端最后一个名称耗尽两天更划算。

目标采用条件区间：仅补基础与质量，力争基础 88～96、质量附加 6～9，约 **94～105/150**；真实图谱再取得部分覆盖时，力争约 **102～118/150**。团队主攻 **100～115** 的可证明覆盖；没有图谱条件时按前一档管理预期。LLM/GPU 是冲刺空间，不纳入保底或对外承诺。

## 3. 主线、条件项与停止规则

- **M 主线**：S0 集成/契约，Q1 质量，R1 CSS、R2 WebGL、R3 Turtle，S1 受限 DSL/策略，F1 最终交付。目标是四个真实适配器；共同静态子集必须贯通，浏览器三后端支持当前线性动画，Turtle 至少支持同一动画 IR 的确定时刻离线采样，不承诺实时播放。
- **C 条件主线**：K1 外部图谱。11/13 12:00 前得到已授权数据来源、调用方式及实体/关系/属性真实样本才启动。未满足立即撤出 8/2 人时，用于基础补漏、适配器/沙盒集成；不得用站内 entityId 演示冒充外部对接。
- **X 冲刺**：X1 LLM 或 X2 GPU。11/17 18:00 只有主线已真实集成通过且剩余 ≥8 团队人时才能选一个；LLM 无服务/预算不启动。11/18 18:00 必须完成闭环，否则关闭入口。
- **D 延后**：通用插件/图数据库重构、任意 Python/JS 执行、全套可视化编辑器、服务端 Chromium 大框架、任意用户 shader、视频编码、选择性完整备份恢复。

R3/Turtle 环境探针 90 分钟、实现总预算 8 小时；无法在目标机器无交互生成 PNG 或正确处理透明/裁剪，则保留 unavailable 和限制说明，转投已验证价值。S1 隔离探针 90 分钟、总预算 11 小时；不能证明 CPU/内存/超时/回收则不开沙盒。B 的 CSS 预算 6 小时、WebGL 10 小时；任一超过预算未闭环，先停该项，不拖质量与现有作品。

这些是默认总预算，包含失败与联调；不是「先写代码 8 小时，再无上限修复」。到点由两人用已通过证据决定删范围或替换任务，记录失分影响。

## 4. 两人责任与 agent 使用

| 范围 | A：平台后端与 Python 引擎 | B：创作前端与浏览器渲染 |
| --- | --- | --- |
| 独占目录 | backend/**、shared/schemas/**、后端脚本 | frontend/**、shared/demo/**、前端脚本 |
| 引擎 | 能力/参数/IR 权威校验、通用任务、Turtle、DSL、质量算法、图谱/LLM 接入 | 统一 Renderer、CSS/WebGL、时间轴/导出、质量/图谱/DSL UI |
| 公共契约 | A 主改接口/OpenAPI/schema，先给真实样例 | B 审查兼容性并接入，不替后端造成功响应 |
| 交付 | 迁移/种子、运行环境、进程/权限、备份/恢复 | 浏览器验收、生产构建、作品/讲解与录屏 |

每人使用自己的 agent 会话，一次委派一个任务切片：允许路径、现行/拟议接口、成功/失败样例、命令、停止时间。先让 agent 读当前实现，再生成最小实现；开发者负责审阅差异、真正运行验收和合入。agent 自报完成不算通过。

同一共享文件只能一个负责人写。两人可以在各自分支同时实现，但每半天要有一次真实接口集成；fixture 只用于等接口期间推进，合入前必须移除默认 mock。跨目录缺陷交对方修，不让两个 agent 互相改同一业务文件。Git push、PR、合并遵守当次授权和仓库规范。

## 5. 复用现有架构，减少新增协议

保留 Next.js/FastAPI/SQLite、Cookie+CSRF、revision、不可变 generation/作品版本、IR 1.0、参数/规则、快照和 browser_upload。不重做现有管理页面。

- B 从现有 Canvas 提取共享的采样/矩阵/世界几何、绘制顺序与导出协议；CSS/WebGL 用同一数值语义，保留 Canvas 的既有 rendererVersion 和旧作品行为。
- A 去除输入模型/服务中写死的 canvas2d，按 capability 与模板 supportedBackends 共同校验。新后端须先创建新模板版本并审核，不改已发布快照。
- 浏览器 Canvas/CSS/WebGL 复用帧上传；Turtle 用 server 任务，同样生成 manifest、走作品保存/鉴权和历史复现。server 任务不接受 frames 上传。
- 新 backend 不改变 IR hash。跨后端比较仅做构图/几何/容差检查，不承诺像素相等；历史复现始终用原 backend/version/环境，不暗中换渲染器。
- 质量报告、图谱快照、LLM 提案均是有版本的增量；旧记录没有新字段时显示「未评估/无快照」，禁止填 0 当通过。
- 沿用 core-demo 800×600、200 节点/2000 顶点/4 层/16 参数、flat、≤5 秒、最多三保存帧等限额。不为适配器扩全量 IR、用户 GLSL 或无限动画。

具体字段和迁移顺序见[接口增量约定](提分阶段接口增量约定.md)。本次只修改规划文档，OpenAPI/后端模型的实施由 A 的 S0 完成。

## 8. 复核后的估时与启动条件

55/65人时是原方案的乐观预算，不是根据新模块实测得到的速度承诺。源码复核新增了Python采样、Canvas版本纠偏、server迁移/worker恢复、DSL会话、来源继承等必需工作；这些分别计入Q1/S0/R3/S1/K1，探针后重新估剩余量，不能额外叠加到冻结期。
