本文件提供集成版的验收入口、四角色演示流程与数据恢复方法。远端 main 已合入 PR #13/#16；本工作分支补充前端适配、验收与清单产物 ID 核验。现场部署须使用最终批准的版本，历史证据保留原版本背景。

## 使用本轮版本

当前工作分支为 `feat/p1-integration-delivery-20261112`，已合入远端 `main@15d79ff`，同步合并点为 `f8542ef`。原两项后端问题采用主线修复，本分支保留额外的清单产物 ID 核验及回归；前端开放六类导出。切回远端 main 时，前端选择项及本分支新增验收脚本未必已合入。

同步后新增迁移 011 已实际应用，完整后端测试 311 项、真实 HTTP 冒烟 40 项、类型检查及生产构建通过；最终浏览器结果见[最新 main 同步验收汇总](../frontend/work-logs/2026-11-12-p1-integration-delivery/main-sync/acceptance-summary.json)。下方 293 项及 36 项等记录属于同步前的独立历史验收，不覆盖为新数字。

标准环境：Node 24.22.2、Python 3.12；Next.js 16.4.5、Canvas2D。根目录按已安装环境执行：

```powershell
uv sync --project backend --locked --extra dev
.\scripts\npm.ps1 ci
$env:CODEPOET_DATA_DIR = Join-Path $PWD '.tools/p1-rehearsal/data'
uv run --project backend python scripts/migrate.py
uv run --project backend python scripts/seed.py --skip-templates
uv run --project backend python scripts/seed_demo.py
.\scripts\npm.ps1 run typecheck
.\scripts\npm.ps1 run build
```

`--skip-templates` 让演示库使用完整版“莲·清正 / 竹·守正 / 四秒·清莲叙事”。PR #16 的标准 `seed.py → seed_demo.py → seed_demo.py` 也已做真实 HTTP 冒烟验证，兼容、幂等，但会保留默认 seed 原有的基础莲模板。不要使用 `--force` 重建已有业务库。

在两个终端分别运行后端与前端。启动后端的终端必须设置相同 `CODEPOET_DATA_DIR`；前端代理目标应在构建与运行时一致：

```powershell
# 终端 A，仓库根目录
$env:CODEPOET_DATA_DIR = Join-Path $PWD '.tools/p1-rehearsal/data'
.\scripts\dev-backend.ps1
```

```powershell
# 终端 B，仓库根目录；默认代理后端 8000
.\scripts\npm.ps1 run start
```

本机本轮使用前端 13160、后端 18160，数据在 `.tools/p1-delivery-20261112/data-p1/`。本机忽略目录中的 `start-services.ps1`、`stop-services.ps1`、`run-check.ps1` 记录了实际运行方式；其他机器使用上方标准命令，不依赖本机绝对路径。修改 `API_PROXY_TARGET` 后须重新生产构建。

## 运行浏览器回归

项目脚本要求已安装 Playwright 和 Chrome；不把 Playwright 放入业务依赖。先在当前进程设置本机 Playwright 所在的 `NODE_PATH` 和验收凭据环境变量；凭据不得作为字面量写入命令历史。各脚本只允许本机隔离部署。

```powershell
$env:CODEPOET_G0_BASE_URL = 'http://127.0.0.1:3000'
$env:CODEPOET_G0_OUTPUT_DIR = 'frontend/work-logs/2026-11-12-p1-integration-delivery/recheck/g0'
node frontend/tests/g0-browser-check.cjs
```

G0 脚本针对基础 seed 的参数名；用独立基础库运行，P1 库使用完整版 demo。

| 脚本 | 地址变量 | 输出变量 |
| --- | --- | --- |
| template-review-browser-check.cjs | CODEPOET_REVIEW_BASE_URL | CODEPOET_REVIEW_OUTPUT_DIR |
| p1-browser-check.cjs | CODEPOET_P1_BASE_URL | CODEPOET_P1_OUTPUT_DIR |
| delivery-browser-check.cjs | CODEPOET_P1_BASE_URL | CODEPOET_DELIVERY_OUTPUT_DIR |
| render-recovery-browser-check.cjs | CODEPOET_P1_BASE_URL | CODEPOET_RECOVERY_OUTPUT_DIR |
| p1b-controls-check.cjs | CODEPOET_P1B_BASE_URL | CODEPOET_P1B_OUTPUT_DIR |

模板/P1/增补/恢复脚本需要 `CODEPOET_ACCEPTANCE_PASSWORD`，仅在内存环境中传递并在结束后移除。退出 0 才算该脚本通过；2 表示后端阻塞，不能按成功计。恢复检查会等待真实五分钟到期，不调系统时钟或数据库时间。

## 备份与恢复

JSON 导出不是完整运行数据备份。完整恢复必须保留 **SQLite 与整个 artifacts 目录**，并使用对应应用版本；只有数据库行而没有 PNG 文件，导出会如实标记产物缺失。

1. 停止当前环境前后端并核对端口，避免备份时继续写入。只处理自己启动的进程。
2. 对已确认的数据目录复制 `codepoet.sqlite3` 与 `artifacts/` 到新的备份目录。数据库使用 SQLite backup API，恢复到新目录，不覆盖原库。
3. 对副本执行 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`，核对 PNG 数量与 SHA256；不要仅以“复制命令退出 0”判断可恢复。
4. 将 `CODEPOET_DATA_DIR` 指向新副本，运行既有迁移后启动后端，重新登录；打开演示目录的三件作品并确认图片可读取。不要对恢复库运行 `--force` 或重置密码。

完整备份包含账号和会话等敏感运行数据，只保存在本地忽略目录或受控存储，不放进 Git 或公开交付截图。公开证据仅保留计数、资源 ID、requestId、结果和图片。

本轮已实际执行上述备份恢复：SQLite integrity_check=ok、外键错误 0，34 个 PNG 的副本哈希及数据库 SHA256 记录均一致；从新副本以 `next start` 启动后，浏览器重新登录、打开三件作品，全部帧哈希通过。见[备份检查](../frontend/work-logs/2026-11-12-p1-integration-delivery/backup-restore-results.json)与[恢复后作品目录](../frontend/work-logs/2026-11-12-p1-integration-delivery/restored-demo-catalog.json)。本轮服务已停止，原测试库、备份及恢复副本均保留在本机忽略目录。
