## 启动

在仓库根目录执行。依赖已安装时可直接构建。

```powershell
uv sync --project backend --locked
.\scripts\setup-node.ps1
.\scripts\npm.ps1 ci
.\scripts\npm.ps1 run typecheck
.\scripts\npm.ps1 run build
```

分别启动 `./scripts/dev-backend.ps1` 和 `./scripts/npm.ps1 run start`，访问 [创作台](http://127.0.0.1:3000)。验证时使用干净的测试数据库和产物目录，按当前后端分支的迁移与种子说明准备四角色。若需要重新构建，先停止生产前端服务。

```powershell
$env:NODE_PATH = 'C:\Users\hp\AppData\Local\npm-cache\_npx\e41f203b7505f1fb\node_modules'
```

退出码 0 表示标准链路通过；2 表示后端契约阻断；1 表示检查失败。标准结果保存在 `frontend/work-logs/2026-11-09-g0-integration/g0-check-results.json`。PowerShell 包装脚本若需向外传递退出码，紧接着执行 `exit $LASTEXITCODE`。

仅为继续诊断后续接口时，可以追加 `--diagnostic-upload`，将当前实际 Canvas 直接上传再检查保存和隔离；结果另写 `g0-diagnostic-results.json`。只要契约阻断仍在，即使后续检查通过，也保持 `g0Passed=false` 和退出码 2。不得用该参数的辅助路径替代标准验收。
