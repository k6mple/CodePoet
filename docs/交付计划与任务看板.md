## 3. 明确缩减的技术范围

- 只保证 Canvas2D；Turtle/CSS/WebGL 返回 unavailable，并写“未实现/选做”，不显示假预览。
- 逻辑画布固定 800×600；最多 200 节点、2000 顶点、4 层；动画1000～5000ms，静态为0；circle/polygon/polyline/group，材质只 flat。
- 动画先做 x/y/rotation/opacity 的线性轨道。其他属性的静态变换仍支持，缩放动画留扩展。
- 保存静态作品 1 PNG；动画 3 帧（0、中间、结束）+IR 时间轴。连续播放从 IR 重建；不把 3 帧 ZIP 称为视频。
- 浏览器 Canvas 导出 PNG → 上传帧 → 后端检查并保存；**不把 Node/Playwright、Xvfb、Ghostscript、cgroup 作为主线依赖**。
- 只接受 JSON IR，禁止 eval/exec/new Function 和任意用户脚本；DSL 编辑器和沙盒管理入口在基础版不出现。
- 一个后端、一个 SQLite、一个 data 目录；少量迁移和幂等种子即可。无 Celery/Redis、图数据库、插件框架、无限撤销、多人协作。
- 审核/版本/私有资源鉴权不能为了省事取消；它们是基础业务和稳定演示的重要部分。

代码各自目录，避免两个人和各自 Codex 同时改同一文件。每天 15 分钟联调，A 提供真实请求响应，B 提供页面复现。每天都要有一个能运行的共同结果。

本计划假设 11/06～11/20 两人每天各有约 5～6 小时有效投入。若明显不足，先停止 P1-C/P2、压缩样式和种子数量，不挪用最后三天联调时间。工时只是排期假设，不是生产率保证。

## 8. 最终演示脚本与交付门槛

按 8～10 分钟准备，不靠开发者修改数据库：

1. 以普通用户登录，查看知识；用 developer 展示模板参数与一次退回/审核历史。
2. 切 expert 审核另一账号提交版本，确认公开模板库发生变化。
3. 普通用户默认生成莲花，调参；非法参数被拒绝，合法参数改变画面。
4. 输入竹节守正，展示命中实体/规则和不同构图；无匹配文本显示提示。
5. 改一个 IR 子树并裁剪，播放/拖动时间轴，点击叙事知识。
6. 保存会话与作品；刷新重开、收藏；从旧快照恢复再继续编辑。
7. 修改规则后复现旧作品，查看旧来源和真实像素比较；发布作品。
8. 展示审计与小 JSON 导出；非法导入不会部分写入。说明 Canvas 已完成、其他后端/沙盒为选做。

最终必须有：运行应用、幂等种子、3 个模板（莲/竹/叙事）、12 条知识、8 条规则、4 个演示角色、3 件作品、一次拒审/归档样例、启动/构建命令、备份说明、验收记录与已知缺口表。严禁为了演示把真实 API 切换为默认 mock。
