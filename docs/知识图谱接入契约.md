# 知识图谱接入契约（K1）——给前端的对接说明

> 面向 B（前端）。后端已实现并有回归覆盖，这份文档是**接口契约 + 边界声明**，
> 不是设计构想。可直接对接的请求/响应样例见
> [`shared/demo/knowledge-graph-examples.json`](../shared/demo/knowledge-graph-examples.json)。

## 一句话

用户选一个外部实体（如「莲」→ Wikidata `Q16528`），后端抓取该实体的属性与一跳关系，
映射到站内知识与规则，生成一份**带来源快照**的不可变生成结果。旧作品复现只读快照，不联网。

## 部署配置（三个环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CODEPOET_KNOWLEDGE_GRAPH_SOURCES` | 空 | 允许的来源白名单，逗号分隔。**空 = 未启用该功能，接口一律 503** |
| `CODEPOET_KNOWLEDGE_GRAPH_MAPPING_FILE` | 空 | 外部实体 → 站内条目的显式映射表（JSON）。空 = 只用标签精确匹配 |
| `CODEPOET_KNOWLEDGE_GRAPH_TIMEOUT_SECONDS` | `10` | 单次抓取超时 |

映射表格式（`shared/demo/knowledge-graph-mappings.json` 是现成样例）：

```json
{"version": 1, "sources": {"wikidata": {
  "Q670887": {"knowledgeId": "knowledge-bamboo", "reason": "Wikidata 的「竹亚科」对应站内「竹」"}
}}}
```

为什么要显式映射表：Wikidata 的「竹」叫**竹亚科**、站内叫**竹**；「梅」站内叫**墨梅**。
靠字符串相似度猜会出错，而错了就等于来源和知识对不上。所以人工确认一次、写进表里。

## 端点

```
POST /api/v1/knowledge-graph/generations
权限：L（登录），写操作需要 X-CSRF-Token
成功：201 Created（新快照，不是 200）
```

请求体：

```json
{"sourceId": "wikidata", "externalEntityId": "Q16528", "backend": "canvas2d", "seed": 42}
```

- `sourceId` 只能是**部署白名单里的键**，不接受 URL —— 否则服务端就成了任意地址代理（SSRF）。
- `backend` 走与普通生成相同的实例级闸门：没启用的后端返回 422 `UNSUPPORTED_CAPABILITY`。

## 响应里你要用的两个字段

### `provenance.externalGraph`

来源快照，**自包含**（实体 label/属性、关系、决策全在里面）。旧记录没有这个字段，按 `null` 读。

| 字段 | 用途 |
| --- | --- |
| `sourceId` / `externalEntityId` | 展示「来源：Wikidata Q16528」并可外链 |
| `fetchedAt` / `contentHash` | 展示「抓取于何时」；内容 hash 用于判断复现时快照是否被改过 |
| `entities[].attributes` | 键形如 `学名(P225)`，括号里是来源属性号，可回溯 |
| `relations[]` | 抓回来的**全部**一跳关系 |
| `mappingDecisions[]` | **真正产生了影响的**事实（见下方「注意事项」） |

`mappingDecisions[].affects` 取值：`rule-selection`（决定了选哪条规则）、
`caption`（进了叙事说明）、`symbols`、`palette`。

### `ir.narrative[].caption`

外部事实进入画面的**唯一**途径：拼接到站内规则自己的 caption 后面。示例：

```
莲：出淤泥而不染，濯清涟而不妖。｜Nelumbo nucifera｜种｜莲属｜分类单元：植物
```

## 五个错误码

| HTTP | code | 什么时候 | 前端建议文案 |
| --- | --- | --- | --- |
| 422 | `KNOWLEDGE_GRAPH_ENTITY_NOT_FOUND` | 来源里没这个实体 | 「这个来源里找不到该条目，换个实体试试」 |
| 422 | `NO_SEMANTIC_MATCH` | 抓到了但映射不到站内知识 | 「该条目还没有对应的站内知识，暂时不能据此生成」 |
| 422 | `UNSUPPORTED_CAPABILITY` | 请求的后端本实例未启用 | 「当前环境不支持该渲染后端」 |
| 503 | `KNOWLEDGE_GRAPH_UNAVAILABLE` | 来源未配置 / 整站不可用 | 「知识图谱来源当前不可用」 |
| 504 | `KNOWLEDGE_GRAPH_TIMEOUT` | 超过超时预算 | 「来源响应太慢，请稍后重试」 |

**503 不会退化成「伪本地生成」**：抓不到就明确失败。否则快照会记下一次没发生过的抓取。

## 前端接入清单

1. **先看能力开关**：`GET /engine/capabilities` → `features.knowledgeGraph`。
   `false` 时**直接隐藏入口**，不要让用户点了才看到 503。
   这个值等于「本实例配了来源」，与接口是否实现是两件事。
2. **错误映射**：按上表把 code 映射成可读文案；4xx 不要自动重试（重试也一样失败）。
   503/504 可以提示重试。
3. **加载态**：单次抓取实测 3~6 秒（真实公网），按钮要有进度反馈，别让用户以为卡死。
4. **展示来源**：作品详情页建议显示 `sourceId + externalEntityId + fetchedAt`，
   这是「来源可追溯」的实际体现；能外链就外链。
5. **不要**把 `externalGraph` 当可选字段做兜底——旧作品确实可能是 `null`，但新作品一定有。

## 注意事项（三条边界，别对外说过头）

### 1. 外部事实改的是叙事，不是像素

`caption` 是 IR 的叙事节点内容。**当前 Canvas 渲染器不把 caption 绘进 PNG**，
页面题记会展示它。所以正确的说法是「外部事实参与了叙事联动」，
**不能**说「外部关系改变了画面」。图形像素仍完全由站内规则决定。

### 2. `mappingDecisions` 只记真正采纳的事实

`relations` 是抓回来的全集，`mappingDecisions` 是**真的进了 caption 的子集**。
两者数量不相等是正常的——caption 有 200 字符预算，装不下的会留在 `relations` 里但不记决策。

如果你要做「这条关系用没用上」的 UI，判断依据是 `mappingDecisions`，不是 `relations`。

### 3. 派生与复现

- `externalGraph` 经过 **ir 派生**和 **subgraph 派生**都会原样继承（这一层没有新增外部事实）。
- **旧作品复现不联网**：复现只读快照，不重新抓来源。来源下线了也不影响历史作品。
- DSL 沙盒（S1）还没做，DSL 派生暂列为后续依赖，不要求本切片覆盖。

## 复现一遍这些结论

```bash
# 后端全量（含 K1 的 26 个用例）
cd backend && python -m unittest discover -s tests

# 真网络端到端（三个意象各 14 项）
python scripts/smoke_knowledge_graph.py --entity Q16528
python scripts/smoke_knowledge_graph.py --entity Q670887   # 竹（竹亚科 → 竹）
python scripts/smoke_knowledge_graph.py --entity Q157763   # 梅（梅 → 墨梅）
```

## 本切片**没有**覆盖的范围

- **K1-B 页面与作品闭环**：前端入口、作品详情展示、演示脚本——不在后端切片内。
